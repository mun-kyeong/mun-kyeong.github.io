## 수업 및 피드백

우선, 우테코 첫주차 후기를 간단히 말해보자면.. 뭔가 에너지를 굉장히 굉장히 많이 쓰게된다는점.. 이틀 다녔는데 한달 다닌 듯한 느낌이 드는건 참 생소했던 것 같다

수업때 배운 내용을 간단히 정리한 내용이다.

### 1.테스트를 진행해야 하는 값은 어디까지일까

---

- 유효성 검사라던가 `입력은 n글자 이하만 가능합니다` 라는 조건이 들어오게 된다면 test에서 진행해야 하는 값은 `n,n+1` 이렇게 두 값만 테스트 진행하면 된다.

<br/>

### 2. **mock 사용을 최대한 지양하자**

---

테스트를 진행하다 보면 제어되지 않는 값들 (랜덤 숫자)을 테스트 하기위해 `mock` 함수를 사용하는 경우가 있다. 공원은 **`mock` 함수 사용을 최대한 지양** 하라고 하는데, 그럼 랜덤 값에 대한 test는 어떻게 진행해야 하는가?

**제어할 수 없는 값은 최대한 그 값을 호출하는 부모가 제어 가능하도록 수정**하자. 예를 들어 이번 `racingCar` 미션에서는 자동차가 움직이기 위한 조건으로 랜덤 숫자가 4 이상일 때 앞으로 전진할 수 있다. <br/>
이때 `Car` 객체의 `move()` 함수 안에서 랜덤 숫자를 생성하고, 판단하고, 앞으로 한칸 움직이는 역할을 부여하는 것이 아니라 `car` 객체를 불러오는 부모로부터 랜덤값을 제어 가능하도록 하는 방법이다.

<br/>

```javascript
//Car 객체에서 랜덤 값 사용 + 관리
move(){
   const randomNum = Math.floor(Math.random() * 10);
   if(randomNum <= 4 ){
      this.#position +=1;
   }
}
```

위와 같이 객체를 사용하게 되면 move() 라는 함수를 test하기 위해선 `randomNum` 이라는 객체를 제어할 수 있어야 한다. 그렇기에 `mock` 함수를 사용할 수 밖에 없게 되는데 이때 이 역할을 부모로 넘긴다면 아래와 같이 리팩도링 가능하다.

<br/>

```javascript

move(number){
   if(number <= 4) {
      this.#position +=1;
   }
}
```

위와 같이 랜덤 숫자 생성을 `Car` 객체를 호출하는 부모에게 맡기고, `Car`에서는 그 값만 받아와서 전진할지, 멈출지만 판단하면 더 좋은 코드가 될 수 있다.

<br/>

### 3. PR피드백 - test 코드를 작성하는 기준

---

미션을 진행하며 궁금했던 점은 **class의 private 변수가 동작하는 것을 확인하기 위한 코드를 작성 할 필요가 있을까**에 대한 의문점이였다. 이전 프리코스 피드백 중에 하나가 test코드를 위한 코드 작성을 지양하라고 했는데, 그렇다면 private 함수와 변수에 대해서는 test를 진행할 수 없는가? 에 대한 고민이 생겼었다.

PR 답변을 통해 정리된 생각으로는 private으로 선언된 함수와 변수들은 대게 **public에서 사용**되게 된다. 그렇다면 **public으로 선언된 함수들이 제대로 동작하는 것을 검증할 수 있다면 private으로 선언된 함수들 또한 테스트 가능하다**고 생각한다.

> 추가로, private과 public 함수를 나누는 기준은 사용자가 건드려도 되는 부분과 건드리면 안되는 부분을 기준으로 나눌 수 있을 것 같다.
